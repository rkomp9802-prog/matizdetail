# MATIZ Detail — лендинг с support-агентом

Лендинг автосервиса-детейлинга и чат-бот поддержки, собранные по SPEC урока 10.
Next.js 16 (App Router) + TypeScript + Tailwind v4. Отдельного бэкенда нет —
API живёт в Route Handlers того же приложения.

## Как отвечает бот

Три уровня, от бесплатного и мгновенного к самому дорогому:

1. **Локальные intents** (`lib/chatBot.ts`) — работают в браузере, без сети и без
   затрат. Цены, услуги, режим работы, запись. Данные берутся из `data/business.ts`.
2. **Своя база FAQ** (Turso) — если посетитель спросил то, на что вы уже написали
   ответ в админке, возвращается ваш текст. Gemini не вызывается.
3. **Gemini** — только для действительно новых вопросов. Одновременно вопрос
   записывается в базу со статусом `pending` и появляется в админке.

Со временем шаг 3 срабатывает всё реже: частые вопросы оседают в базе с вашими
формулировками.

Посетитель может прислать фото или голосовое. Бот их не разбирает — он не умеет
ни смотреть снимок, ни слушать запись, — поэтому подтверждает приём, а само
вложение уходит владельцу в Telegram и остаётся в админке.

## Запуск

```bash
npm install
cp .env.example .env.local   # заполните ключи
npm run db:migrate           # создаст таблицы questions и chat_messages
npm run db:seed              # заготовка частых вопросов
npm run dev
```

Открыть http://localhost:3000, админка — http://localhost:3000/admin

## Переменные окружения

| Переменная | Когда нужна | Что будет без неё |
|---|---|---|
| `GEMINI_API_KEY` | Этап 2 | Бот отвечает только локальными intents; незнакомые вопросы всё равно копятся в базе |
| `GEMINI_MODEL` | необязательно | По умолчанию `gemini-2.5-flash` |
| `TURSO_DATABASE_URL` | Этап 3 | База FAQ отключается, вопросы не логируются |
| `TURSO_AUTH_TOKEN` | только для облака Turso | Для локального `file:local.db` не нужен |
| `ADMIN_PASSWORD` | Этап 3 | В админку не войти |
| `TELEGRAM_BOT_TOKEN` | необязательно | Уведомления не отправляются, остальное работает |
| `TELEGRAM_CHAT_ID` | необязательно | То же самое |
| `TELEGRAM_WEBHOOK_SECRET` | для бота в Telegram | Webhook примет запрос от любого, кто знает адрес |

Ключ Gemini — в [Google AI Studio](https://aistudio.google.com/apikey).
Локально базу можно не заводить в облаке: `TURSO_DATABASE_URL=file:local.db`
создаст SQLite-файл рядом с проектом.

## Заготовка частых вопросов

`npm run db:seed` заливает в базу набор типовых вопросов, чтобы бот не тратил
запросы к Gemini на одно и то же. Скрипт идемпотентный — дубликатов не создаст.

Вопросы, которые уже ловят локальные intents (цены, график, запись, телефон),
в заготовку намеренно не попали: они и так отвечаются мгновенно и бесплатно,
ещё до обращения к базе.

Часть записей приходит **без ответа** — это частые вопросы, ответ на которые
знаешь только ты (оплата, адрес, скидки, предоплата). Они ждут в админке с уже
проставленными ключевыми словами. Пока ответ не вписан, такие вопросы
по-прежнему уходят в Gemini.

## Тёмная и светлая тема

Переключатель в шапке сайта и в админке. Выбор запоминается в браузере гостя;
пока он ничего не выбрал — берётся системная настройка. Тема применяется
скриптом в `<head>` до отрисовки, поэтому страница не моргает белым.

Палитра — обычные CSS-переменные в `app/globals.css`, а `@theme` только
ссылается на них. Поэтому смена темы не требует классов вроде `dark:bg-...`:
достаточно пользоваться токенами `bg-card`, `text-ink`, `border-line`.

## Данные сервиса

Вкладка `/admin/info`. Здесь владелец правит телефон, режим работы, адрес,
цены, а также **что мы делаем** и **чего НЕ делаем**. Эти данные:

- подставляются на сайт — в шапку, карточки услуг и подвал;
- питают локальные intents (цены, график, запись);
- уходят в system-инструкцию Gemini.

Поле «чего мы НЕ делаем» — самое важное. Без него Gemini додумывает за вас:
на тесте он сам заявил клиенту, что выезда на дом нет, хотя мы этого нигде
не писали. Заполните его — и модель будет отказывать по вашим правилам,
а не по своим догадкам.

Пока таблица `business_info` пуста, всё берётся из `data/business.ts`.

## Telegram: бот отвечает клиентам

Клиент может писать боту прямо в Telegram и получит те же ответы, что и
в виджете: intents → своя база → Gemini. Переписка попадает в ту же админку,
диалог помечается как `tg-<chat id>`.

Подключение (нужен публичный HTTPS-адрес, на localhost webhook не работает):

```bash
npm run tg:webhook -- https://ваш-домен.vercel.app
```

`TELEGRAM_WEBHOOK_SECRET` передаётся Telegram при установке и потом приходит
в заголовке каждого запроса — так роут отличает Telegram от постороннего,
узнавшего адрес.

## Уведомления в Telegram

Заведите бота у @BotFather, узнайте свой chat id у @userinfobot и впишите обе
переменные в `.env.local`. После этого вам будут приходить:

- вопросы, на которые у бота нет своего ответа (с пометкой, ответил ли Gemini);
- фото и голосовые от посетителей — прямо файлом, с подписью.

Без переменных чат работает как обычно, уведомления просто не отправляются.

## Админка

`/admin`, вход по `ADMIN_PASSWORD` (httpOnly-cookie на 7 дней, проверяется в `proxy.ts`).

Две вкладки: **База вопросов** и **Переписка** — вся история чата, включая фото
и голосовые. Вложения отдаются отдельным защищённым роутом
`/api/admin/media/[id]`, чтобы не тянуть мегабайты base64 в HTML страницы.

В базе вопросов два списка: **без ответа** (сначала самые частые — колонка «спросили N раз») и
**уже отвечены** (можно раскрыть и поправить). Вопросы можно добавлять и вручную,
не дожидаясь посетителей.

### Ключевые слова

У каждого вопроса есть поле ключевых слов. Они решают проблему падежей, времён и
синонимов: сравнение идёт по основе слова, поэтому «мотоцикл» ловит и «мотоциклам»,
и «мотоциклы».

- Достаточно **одного** совпадения — пишите синонимы через запятую: `мотоцикл, байк, мото`.
- Поэтому слова должны быть **отличительными**. Общие («цена», «есть», «сколько»)
  отбрасываются автоматически — по ним сработало бы что угодно.
- Ключевое слово из нескольких слов — это фраза: засчитывается, только если в
  вопросе есть все её части.
- При первом попадании вопроса в базу ключевые слова генерируются автоматически из
  самого вопроса — дальше правьте руками.

Параллельно работает сравнение строк целиком (коэффициент Дайса, порог `0.6` в
`lib/qaMatch.ts`) — оно ловит похожие формулировки без всяких ключевых слов.

## Структура

```
app/
  api/chat/route.ts          # FAQ-база → Gemini, приём вложений, Telegram
  api/chat/log/route.ts      # журнал сообщений, отвеченных локально
  api/admin/media/[id]/route.ts
  api/admin/questions/route.ts
  api/admin/login/route.ts
  admin/                     # панель и форма входа
components/chat/             # виджет
components/landing/          # секции лендинга
hooks/useChat.ts             # состояние чата и три уровня ответа
lib/chatBot.ts               # локальные intents
lib/qaMatch.ts               # ключевые слова, стеммер, поиск ответа
lib/gemini.ts                # обёртка над Gemini
lib/turso.ts                 # клиент базы
lib/chatLog.ts               # переписка и вложения
lib/telegram.ts              # уведомления владельцу
lib/media.ts                 # сжатие фото и запись голоса в браузере
lib/answer.ts                # общая цепочка ответа для сайта и Telegram
lib/businessInfo.ts          # данные сервиса, редактируемые в админке
data/business.ts             # единый источник данных о бизнесе
proxy.ts                     # защита /admin и /api/admin
```

## Деплой на Vercel

Импортировать репозиторий, прописать те же переменные окружения в настройках
проекта. `TURSO_DATABASE_URL` на проде должен указывать на облачную базу
(`libsql://…`), а не на локальный файл, — и там уже обязателен `TURSO_AUTH_TOKEN`.

## Что осознанно упрощено

Без SSE-стриминга, без автотестов, без ролей в админке (один пароль на всех) и
без векторного поиска. Подробнее — в разделе 12 исходного SPEC.

История переписки в спеке не сохранялась, но её потребовалось видеть в админке —
поэтому появились таблица `chat_messages` и `session_id` (одна вкладка = один
диалог, `sessionStorage`).

Фото и голосовые лежат в самой базе в base64: отдельное файловое хранилище
потребовало бы ещё один сервис и токен. Фото сжимается в браузере до ~200 КБ,
голосовое ограничено минутой. Если вложений станут десятки тысяч, это стоит
переносить в Vercel Blob или S3.
